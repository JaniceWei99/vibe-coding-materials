什么是 CI/CD？

🔄

CI — 持续集成

Continuous Integration

每次你提交代码（git push），系统自动执行：

  • 自动编译代码
  • 自动跑测试
  • 自动检查代码质量
  • 有问题？立刻通知你
🚀

CD — 持续部署

Continuous Deployment

测试全通过后，系统自动执行：

  • 自动打包应用
  • 自动部署到服务器
  • 自动更新线上版本
  • 有问题？自动回滚

一句话：你只管写代码和git push，剩下的全自动。

🏭

用生活来理解CI/CD

🍔 想象你开了一家汉堡店：

❌ 没有CI/CD：每次客人点餐，你亲自去买菜、洗菜、切菜、做饼、烤肉、组装、端上桌……

→ 累死，还容易出错（盐放多了、肉烤糊了）

✅ 有CI/CD：你设计好菜单和配方，流水线自动运转：

→ 原料自动检查质量（CI：测试）

→ 按标准流程自动制作（CD：打包+部署）

→ 成品自动送到客人手里（上线）

你只需要：设计新菜品（写代码）+ 把配方放上流水线（git push）

Harness的核心概念（超简版）

🏗️ Pipeline
流水线
⊃
📋 Stage
阶段
⊃
⚙️ Step
步骤

Pipeline（流水线）

整个自动化流程。
类比：一条完整的生产线

例：从代码到上线的全过程

Stage（阶段）

流水线中的一个大环节。
类比：生产线上的一个工作站

例：构建阶段、测试阶段、部署阶段

Step（步骤）

阶段中的一个具体操作。
类比：工作站上的一个动作

例：运行npm install、执行测试脚本

Trigger：什么时候自动触发？

📨

代码推送触发

你 git push 到主分支 → Pipeline自动运行

最常见的触发方式

🔀

PR合并触发

Pull Request被合并 → 自动构建+部署

团队协作最佳实践

⏰

定时触发

每天凌晨2点自动跑测试 → 第二天上班看结果

适合跑耗时长的测试

🖱️

手动触发

点一个按钮 → 一键部署

重要发布时使用

💡 类比：闹钟（定时触发）vs 门铃（事件触发）vs 遥控器（手动触发）

📖 讲授

🏁 Feature Flags：功能开关

Harness另一个酷炫的功能

❌ 没有Feature Flags

新功能写完了→直接上线→所有用户立刻看到

万一有Bug？→ 所有人都受影响 💥

想回滚？→ 重新部署，可能要好几分钟

VS

✅ 有Feature Flags

新功能写完了→上线但默认关闭

先给10%的用户试用→没问题→开给所有人

有Bug？→ 一秒关闭，不需要重新部署！

🎮 就像游戏里的技能开关：功能已经部署了，但你可以随时开/关，还可以选择对谁开放。

📖 举个栗子

Feature Flags的真实场景

🛒

电商App新结账流程

重新设计了结账页面，但不确定用户喜不喜欢。

→ 先开给5%的用户，观察转化率

→ 数据好？→ 扩大到100%

→ 数据差？→ 一键关闭，回到旧版

🎓

你的课程表App

加了一个"AI推荐选课"功能，但还在测试。

→ 只对自己和室友开放测试

→ 确认OK后 → 开放给全班

→ 再开放给 → 全校

Feature Flags = 让发布不再是"赌博" 🎲
