和AI说话的艺术

Prompt Engineering——不是玄学，是技术

📖 讲授

好Prompt vs 坏Prompt

❌

坏 Prompt

帮我做一个网站

问题：太模糊！做什么网站？长什么样？有什么功能？AI只能瞎猜。

VS
✅

好 Prompt

帮我做一个待办事项网页： - 单个HTML文件 - 可以添加/删除任务 - 任务可以标记完成 - 深色主题 - 数据保存在浏览器本地

清晰！AI知道该做什么。

📖 讲授

🔑 5个Prompt核心技巧

1️⃣ 说清楚"要什么"

描述功能、外观、技术要求。
不要说"怎么做"，让AI自己决定实现方式。

2️⃣ 给上下文

告诉AI项目背景、使用场景、目标用户。
比如："这是给[某类用户群体]用的课程表应用"

3️⃣ 一次一件事

不要一口气提20个需求。
先做核心功能，再逐步添加。

4️⃣ 用例子说明

"类似于微信读书的书架页面"
"参考苹果官网那种简约风格"

5️⃣ 不满意就迭代——告诉AI哪里不对，让它改。对话轮次不限！

📖 讲授

📝 万能Prompt模板

// 用这个模板，几乎可以做任何项目： 我想做一个 [项目类型]，具体要求如下： 功能需求： - [核心功能1] - [核心功能2] - [核心功能3] 技术要求： - [用什么技术，如：单个HTML文件] - [数据存储方式，如：localStorage] 设计要求： - [风格，如：现代简约深色主题] - [参考，如：类似notion的设计风格] 用户：[谁会用，如：在校人群/职场人士/家长等]

💡 不需要每次都填满，但越具体，结果越好

🔄 迭代对话的正确姿势

修改外观

颜色太亮了，整体用深色背景，按钮用蓝紫渐变色

添加功能

给每个任务加一个截止日期的功能，过期的任务标红

修复问题

添加任务后输入框没有清空，而且新任务应该显示在最上面

优化体验

输入框里按回车就能添加任务，不需要点按钮

为什么需要Git？

😱 没有Git的世界

我的项目/ ├── index.html ├── index_备份.html ├── index_备份2.html ├── index_备份_最终版.html ├── index_备份_最终版_真的最终版.html ├── index_备份_最终版_真的最终版_老师看这个.html └── index_我放弃了.html

😎 有Git的世界

我的项目/ └── index.html ← 就一个文件，但Git记住了每一次修改

Git = 无限次Ctrl+Z + 完整的修改记录 + 多人协作

📖 讲授

Git的3个核心概念

📦

仓库 (Repository)

你的项目文件夹。
告诉Git"帮我管理这个文件夹"。

git init
📸

提交 (Commit)

给项目拍一张"快照"。
随时可以回到这个状态。

git add . git commit -m "完成首页"
🌿

分支 (Branch)

平行宇宙。
在分支上瞎搞不影响主线。

git checkout -b 新功能

💡 在TRAE中，很多Git操作可以让AI帮你执行，不需要记命令。

🖥️ 演示

在TRAE中使用Git

  • 1
    初始化Git仓库
    告诉AI："帮我在这个项目初始化Git仓库"
  • 2
    提交代码
    TRAE左侧有Git面板，点击 "+" 暂存，写提交信息，点提交
  • 3
    查看历史
    可以看到每次提交的记录，随时回滚
  • 4
    好习惯：做完一个功能就提交一次
    这样AI改崩了，你可以轻松回到上一个好的版本

🎯 Vibe Coding黄金法则：每次AI改完代码、你觉得OK，就 git commit 一下！

🎯 项目：智能记事本

核心功能

  • ✏️ 添加、编辑、删除笔记

  • 🔍 搜索笔记内容

🛠️ 技术栈

⏱️ 预计耗时

🛠️ 实战 · Step 1

第一步：创建项目 + 初始化

  • 1
    在TRAE中创建一个新文件夹：smart-notes
  • 2
    打开Agent对话框，输入第一个Prompt：
帮我创建一个智能记事本Web应用，要求： 1. 单个HTML文件（内联CSS和JS） 2. 深色主题，现代设计风格，类似Notion 3. 功能： - 可以添加新笔记（标题+内容） - 笔记以卡片形式展示 - 可以删除笔记 - 数据用localStorage保存，刷新不丢失 4. 顶部有应用名称"我的智能笔记" 5. 有一个输入区域（标题输入框+内容文本框+添加按钮） 6. 笔记卡片显示标题、内容和创建时间 请先做好这个基础版本。
🛠️ 实战 · Step 2

第二步：看效果 + 初始化Git

  • 1
    AI生成了代码？ 在浏览器中打开HTML文件看效果
    右键文件 → 在浏览器中打开 / 或用Live Server
  • 2
    效果满意？ 初始化Git仓库并提交
    告诉AI："帮我初始化Git仓库并提交当前代码，提交信息写'初始版本：基础记事本功能'"
  • 3
    效果不满意？ 告诉AI哪里不对，让它改！
    例如："按钮太小了"、"颜色太丑"、"布局不对"

✅ 满意了就提交，不满意就迭代——这就是Vibe Coding工作流

🛠️ 实战 · Step 3

第三步：添加搜索功能

基础版OK了？继续加功能！

// 发送给AI： 给记事本加一个搜索功能： - 在顶部添加一个搜索输入框 - 输入关键词时实时过滤笔记 - 搜索匹配标题和内容 - 没有匹配结果时显示"没有找到相关笔记" - 搜索框有一个放大镜图标

✅ AI改完后，测试一下搜索功能，OK了就 git commit！

// 让AI帮你提交： 帮我提交代码，提交信息："添加搜索功能"
🛠️ 实战 · Step 4

第四步：加入分类标签

// 发送给AI： 给笔记添加分类标签功能： - 预设标签：学习、生活、想法、待办 - 创建笔记时可以选择一个标签 - 笔记卡片上显示对应的标签（用不同颜色） - 顶部加标签筛选按钮，点击可以筛选特定分类 - 标签筛选和搜索可以同时使用

注意看AI是怎么在现有代码基础上添加新功能的！
它不需要你告诉它现有的代码结构——Agent模式下AI能读懂你的项目。

第五步：美化 + 动画

// 最后润色一下： 帮我美化一下这个记事本应用： 1. 笔记卡片加入悬停放大效果 2. 添加和删除笔记时有淡入淡出动画 3. 空状态（没有笔记时）显示一个友好的提示和图标 4. 让整个界面更有高级感，参考Apple的设计风格 5. 支持手机浏览（响应式布局）

进阶技巧 + 避坑指南

从"能用"到"好用"的关键一步

� 讲授

技巧1：先规划，再动手

❌ 新手做法

打开TRAE，直接说"帮我做一个XXX"

结果：AI东一下西一下，最后做出来的东西和想的不一样，越改越乱。

✅ 进阶做法

先花点时间想清楚：

  • 这个项目要解决什么问题？
  • 核心功能有哪些？（列3-5个）
  • 先做哪个，后做哪个？（排优先级）
  • 大概长什么样？（画个草图）

💡 甚至可以先让AI帮你规划！试试对AI说：
"我想做一个XXX，帮我列出功能清单和开发步骤"

📖 讲授

技巧2：分步开发，小步快跑

🏃 正确的节奏

1. 做核心功能 → 2. 测试 & 提交 → 3. 加一个功能 → 4. 测试 & 提交 → 5. 美化UI → 6. 测试 & 提交

"Rome was not built in a day."
先让它能跑起来，再让它变好看，最后让它变强大。

📖 讲授

🚧 避坑指南：Vibe Coding常见翻车

�️ 坑1：越改越乱

现象：改了10轮，代码变得一团糟
解法：及时 git commit！改崩了就回滚到上一个好的版本重新来

🕳️ 坑2：AI自说自话

现象：AI加了一堆你没要的功能
解法：Prompt要明确说"只做XXX，不要加其他功能"

🕳️ 坑3：完全不看代码

现象：AI写了有bug的代码但你没发现
解法：至少扫一眼生成的代码，看不懂的让AI解释

🕳️ 坑4：一次说太多

现象：给AI发了一大段需求，结果只做了一半
解法：每次只提1-2个具体改动

📝 总结

🐛 当AI犯错时——Debug技巧

1. 描述现象

点击添加按钮后，笔记没有 出现在页面上，但是刷新 页面后就出现了

告诉AI你看到了什么和你期望的是什么

2. 复制错误信息

浏览器控制台报错： Uncaught TypeError: Cannot read property 'value' of null

按 F12 打开浏览器开发者工具，看Console

3. 让AI解释代码

解释一下这个addNote函数 在做什么，为什么点击按钮 后笔记没有显示？

不懂的代码让AI解释，边学边修

4. 终极方案：回滚

帮我撤销上一次的修改， 回到之前能用的版本

这就是为什么要经常 git commit！

🚀 项目部署上线（免费方案）

GitHub Pages（最简单）

  • 仓库 Settings → Pages → 选择 main 分支 → Save
  • 等待 1-2 分钟，自动生成公开 URL
  • 适合静态站点/单文件项目（如我们的记事本）
  • 每次 push 代码自动更新页面

Vercel / Netlify（自动化更强）

  • 用 GitHub 账号登录 → Import 项目 → 一键 Deploy
  • 支持自定义域名、环境变量、Serverless Functions
  • 每次 push 自动部署，无需手动操作
  • 适合多页应用、前端框架项目（React/Vue等）

💡 课堂项目可直接发布到 GitHub Pages，拿到可分享链接，发给朋友们看——这就是正反馈闭环！

🔗 前后端分离：现代Web开发的基石

什么是前后端分离？

前端（界面/交互）与后端（业务逻辑/数据存储）各自独立，通过 API（接口）通信。

就像餐厅——前厅（服务员/菜单/装潢）和后厨（厨师/食材/烹饪）各司其职，用"点菜单"沟通。

优势 vs 劣势

优势劣势
并行开发、效率高系统复杂度提高
一套后端 → 多端复用SEO 需要 SSR 处理
技术栈自由选择首屏加载可能更慢
维护与迭代方便入门学习曲线陡
📖 讲授

🏪 案例对比：校园二手平台

🔴

传统模式

  • 服务器拼接 HTML 返回整页
  • 换客户端（App/小程序）→ 重写一套
  • 前后端耦合，改UI也要动后端
VS
🟢

分离模式

  • 后端提供 /api/products 等接口
  • Web/小程序/App 共用同一套 API
  • 前端自由迭代，后端独立扩展

📌 先从单文件 HTML 起步，等项目长大后再引入分离架构。循序渐进最重要。

💰 Token 与费用：用AI的成本

什么是 Token？

AI 将文字/代码切分为 Token（约 ¾ 个英文单词或 ½ 个中文字）。

每次对话的输入和输出都会消耗 Token，按量计费。

小项目估算：约 10K 输入 + 20K 输出 Token

主流模型价格（2025年中）

模型输入$/百万输出$/百万
GPT-4o2.5010.00
GPT-4o-mini0.150.60
Claude Sonnet 43.0015.00
Claude Haiku0.251.25
DeepSeek V30.271.10

📌 课堂建议：TRAE 完全免费为主，ChatGPT/Claude 免费版辅助问答。小项目成本几毛美元以内。

👥 团队 Vibe Coding 分工

常见角色

  • PM：需求定义、功能优先级
  • 前端：页面/交互，与AI协作产出UI

Git 分支：feature/* 分工 → 合并 main；先约定再动手！

📱 App 上架与小程序发布

上架流程要点

  • iOS：Apple 开发者账号（$99/年）→ 证书 → Xcode → TestFlight → 审核 1-3 天
  • Android：Google Play（$25）或国内各厂商商店分别注册提交
  • 鸿蒙：华为开发者联盟 + DevEco Studio（ArkTS）
  • 微信小程序：公众平台注册 → 开发者工具 → 体验版 → 审核 1-7 天

个人 vs 企业

小程序个人类目受限：无法接微信支付、电商、直播、社交。

企业认证后放宽限制，可做完整商业应用。
