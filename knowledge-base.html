🧠 第一章：AI编程与Vibe Coding

1.1 AI编程发展历程

时间事件意义
2021年6月GitHub Copilot 预览版发布第一个AI代码补全工具
2022年11月ChatGPT 横空出世AI从实验室走向大众
2023年3月GPT-4 发布代码能力质的飞跃，能理解复杂需求
2024年Cursor 爆火AI IDE革命开始，编程方式巨变
2025年2月Andrej Karpathy 提出 "Vibe Coding"定义了AI编程新时代
💡 关键人物

Andrej Karpathy：前OpenAI联合创始人、前特斯拉AI总监、Stanford CS博士。他在X（推特）上的一条推文，正式给这种新编程方式命名为 "Vibe Coding"。

1.2 什么是Vibe Coding

Vibe Coding（氛围编程）是一种全新的编程方式：你用自然语言描述需求，AI帮你写代码。你不需要精通任何编程语言，只需要会"说话"。

对比项传统编程Vibe Coding
核心技能学语法、记API描述需求、指导AI
写代码的人你自己AI写，你审查
Debug自己查错告诉AI现象，让AI修
学习周期几个月到几年几分钟入门
你的角色程序员导演（AI是编剧+演员）
✅ 一句话总结

Vibe Coding = 你是导演，AI是编剧+程序员。你说戏，AI干活。

1.3 Copilot vs Agent 模式

特性Copilot（副驾驶）Agent（智能体）
工作方式你在写代码，AI帮你补全你描述需求，AI自己规划执行
类比你在开车，AI帮你导航AI在开车，你在导航
能力范围代码补全、建议创建文件、写代码、运行、修Bug
代表工具GitHub CopilotTRAE、Cursor、Windsurf

本课程使用的是 Agent模式，这才是真正的Vibe Coding。

1.4 为什么学Vibe Coding

  • 10倍效率提升：以前一周的项目，现在可能一天搞定
  • 就业竞争力：企业正在招"会用AI编程的人"，这正在变成必备技能
  • 实现你的想法：有APP想法？小工具？小游戏？现在你可以自己做出来
  • 门槛极低：不需要精通编程语言，会描述需求就能开始

🗣️ 第三章：Prompt Engineering

3.1 好Prompt vs 坏Prompt

坏 Prompt ❌好 Prompt ✅
"帮我做一个网站""帮我做一个待办事项网页：单个HTML文件，可以添加/删除任务，深色主题，数据保存在浏览器本地"
"代码有Bug""点击添加按钮后，任务没有出现在列表里，但控制台没有报错"
"优化一下""给每个任务卡片加悬停效果，添加任务时有淡入动画"
✅ 核心原则

像跟同事描述需求一样跟AI说话——越具体，结果越好。

3.2 5个核心技巧

  1. 说清楚"要什么"：描述功能、外观、技术要求。不要说"怎么做"，让AI自己决定实现方式。
  2. 给上下文：告诉AI项目背景、使用场景、目标用户。如"这是给大学生用的课程表应用"。
  3. 一次一件事：不要一口气提20个需求。先做核心功能，再逐步添加。
  4. 用例子说明：如"类似微信读书的书架页面"、"参考苹果官网的简约风格"。
  5. 不满意就迭代：告诉AI哪里不对，让它改。对话轮次不限！

3.3 万能Prompt模板

我想做一个 [项目类型]，具体要求如下：

功能需求：
- [核心功能1]
- [核心功能2]
- [核心功能3]

技术要求：
- [用什么技术，如：单个HTML文件]
- [数据存储方式，如：localStorage]

设计要求：
- [风格，如：现代简约深色主题]
- [参考，如：类似notion的设计风格]

用户：[谁会用，如：大学生]
💡 提示

不需要每次都填满所有字段，但越具体结果越好。这个模板几乎适用于任何Web项目。

3.4 迭代对话技巧

修改外观

颜色太亮了，整体用深色背景，按钮用蓝紫渐变色

添加功能

给每个任务加一个截止日期的功能，过期的任务标红

修复问题

添加任务后输入框没有清空，而且新任务应该显示在最上面

优化体验

输入框里按回车就能添加任务，不需要点按钮

让AI解释

解释一下这段代码的第15行到第30行是做什么的

⏳ 第四章：Git版本控制

4.1 为什么需要Git

没有Git的世界：

我的项目/
├── index.html
├── index_备份.html
├── index_备份2.html
├── index_备份_最终版.html
├── index_备份_最终版_真的最终版.html
└── index_我放弃了.html

有Git的世界：

我的项目/
└── index.html    ← 就一个文件，Git记住了每一次修改

Git = 无限次Ctrl+Z + 完整的修改记录 + 多人协作

4.2 核心概念

概念类比命令
仓库 (Repository)你的项目文件夹，告诉Git"帮我管理这个文件夹"git init
暂存 (Stage)选好要拍快照的文件git add .
提交 (Commit)给项目拍一张"快照"，随时可回到这个状态git commit -m "说明"
分支 (Branch)平行宇宙，在分支上瞎搞不影响主线git checkout -b 新功能
推送 (Push)把快照上传到云端git push
✅ 口诀

选文件（add）→ 拍快照（commit）→ 传云端（push）

4.3 常用命令速查

命令作用使用场景
git init初始化Git仓库新项目第一次用Git
git add .把所有文件加入暂存区准备提交前
git commit -m "说明"提交一次快照完成一个功能后
git status查看当前状态看看有哪些文件改了
git log --oneline查看提交历史回顾之前做了什么
git push origin main推送到远程备份到GitHub
git pull拉取远程最新同步他人的修改
git checkout -- .撤销未提交的修改改坏了，想回到上次提交
git reset --hard HEAD~1回退到上一次提交提交错了，想撤销

4.4 在TRAE中使用Git

TRAE左侧有Git面板（分叉图标），支持图形化操作：

  • 点 "+" → 相当于 git add
  • 写备注，点 "✓" → 相当于 git commit
  • 点 "推送" → 相当于 git push

你也可以直接让AI帮你操作Git：

帮我把当前的代码提交到Git，备注写"完成基础布局"
💡 Vibe Coding时代的Git

AI连Git都能帮你操作。不用记命令，用自然语言就能完成版本控制。

4.5 GitHub远程仓库

创建GitHub仓库

1注册GitHub账号

访问 github.com，用邮箱注册一个免费账号。

2创建新仓库

点右上角 "+" → "New repository" → 输入项目名 → Create。

3关联本地项目
git remote add origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main
⚠️ 注意

第一次推送时需要GitHub登录认证。TRAE可能会弹出登录窗口，按提示操作即可。

🧠 第六章：进阶技巧与避坑指南

6.1 先规划再动手

❌ 新手做法

打开TRAE，直接说"帮我做一个XXX"。结果AI东一下西一下，越改越乱。

✅ 进阶做法

先花5分钟想清楚：

  1. 这个项目要解决什么问题？
  2. 核心功能有哪些？（列3-5个）
  3. 先做哪个，后做哪个？（排优先级）
  4. 大概长什么样？（画个草图）

甚至可以先让AI帮你规划：

我想做一个XXX，帮我列出功能清单和开发步骤

6.2 分步开发，小步快跑

正确节奏：

  1. 做核心功能 → 测试 → git commit
  2. 加一个功能 → 测试 → git commit
  3. 美化UI → 测试 → git commit
  4. 加进阶功能 → 测试 → git commit
💡 金句

"Rome was not built in a day."
先让它能跑起来，再让它变好看，最后让它变强大。

6.3 四大常见翻车

坑现象解法
🕳️ 越改越乱改了10轮，代码一团糟及时 git commit！改崩了就回滚到上一个好版本
🕳️ AI自说自话AI加了一堆你没要的功能Prompt明确说"只做XXX，不要加其他功能"
🕳️ 完全不看代码AI写了有Bug的代码没发现至少扫一眼生成的代码，看不懂的让AI解释
🕳️ 一次说太多发了一大段需求，只做了一半每次只提1-2个具体改动
⚠️ 三句话记住
  1. 🧠 先想清楚再开始（5分钟规划省30分钟修改）
  2. 📦 大任务拆小步骤（一次一个功能，步步为营）
  3. 🔍 每一步都验证效果（不要盲目信任AI）

6.4 Debug技巧

技巧1：把错误信息直接发给AI

这段代码运行后报了这个错误：
[粘贴完整的报错信息]

技巧2：描述"现象"而不是"猜测"

❌ 不好："JavaScript有bug"
✅ 好："点击添加按钮后，笔记没有出现在列表里，但控制台没有报错"

技巧3：让AI解释代码

解释一下这段代码是做什么的，特别是第15行到第30行

技巧4：实在搞不定？回滚重来

帮我撤销上一次的修改，回到之前能用的版本

Console（控制台）标签页会显示JavaScript错误信息。把这些错误信息复制给AI，它能精准定位问题。

🌐 第七章：项目部署上线

7.1 静态页面部署概述

你做的HTML项目（如记事本、个人网页）都是静态页面，部署非常简单。这意味着不需要服务器端语言，只需要一个"文件托管服务"。

🏗️ 第九章：前后端分离

9.1 什么是前后端分离

前后端分离是一种软件架构模式：把用户看到的界面（前端）和处理数据的服务器逻辑（后端）分成两个独立的项目，通过API接口通信。

概念类比技术举例
前端餐厅的大堂（菜单、装修、服务员）HTML/CSS/JS、React、Vue、小程序
后端餐厅的厨房（做菜、管库存、算账）Node.js、Python、Java、Go
API接口传菜窗口（前台和后厨的沟通方式）REST API、GraphQL
// 未分离（传统模式）：
用户 → 服务器（同时生成页面 + 处理数据）→ 返回完整HTML页面

// 前后端分离：
用户 → 前端（浏览器渲染页面）←API请求/响应→ 后端（只处理数据）

9.2 优势与劣势

优势

  • 独立开发：前端和后端团队可以并行工作，互不阻塞
  • 一套后端，多个前端：同一个API可以同时服务网页、App、小程序
  • 技术自由：前端可以用React，后端可以用Python，各选最合适的
  • 更好的用户体验：页面不用整页刷新，像原生App一样流畅（SPA）
  • 便于维护：改前端不影响后端，反之亦然

劣势

  • 复杂度增加：需要设计API、处理跨域、管理两个项目
  • SEO不友好：纯前端渲染的页面，搜索引擎不容易抓取（需要SSR解决）
  • 首屏加载慢：需要先下载JS框架再渲染页面
  • 学习成本高：对新手来说需要理解更多概念

9.3 实际案例对比：校园二手交易平台

未分离的做法（传统）

// 用户访问商品列表页
1. 浏览器请求 → 服务器
2. 服务器查数据库，获取商品列表
3. 服务器用模板引擎把数据"塞进"HTML
4. 返回完整的HTML页面给浏览器
5. 用户点击下一页 → 整个页面重新加载

问题：
- 想做App？后端逻辑全写在HTML模板里，没法复用
- 想做小程序？再抄一遍后端代码
- 页面每次操作都要整页刷新，体验差

前后端分离的做法

// 后端只提供API：
GET /api/products          → 返回商品JSON数据
POST /api/products         → 发布新商品
GET /api/products/123      → 获取商品详情

// 前端（网页版）：
React/Vue 调用API → 渲染商品列表 → 丝滑翻页

// 前端（微信小程序）：
小程序调用同一套API → 渲染小程序界面

// 前端（App）：
Flutter/React Native 调用同一套API → 渲染App界面

一套后端API，三个前端共用！
✅ 一句话总结

前后端分离 = 厨房和大堂分开经营。厨房只管做菜（API），大堂可以开很多家分店（网页、App、小程序），都从同一个厨房取菜。

🪙 第十二章：Token与费用

12.1 什么是Token

Token 是AI模型处理文本的基本单位。你可以理解为"词块"——大约1个中文字 ≈ 1-2个Token，1个英文单词 ≈ 1个Token。

// Token计算示例：
"Hello, world!"              → 约 4 个 Token
"你好，世界！"               → 约 6 个 Token
一段200行的Python代码         → 约 2000-4000 个 Token
一个完整的HTML网页（500行）   → 约 3000-6000 个 Token

AI对话时，输入（你的Prompt + 上下文）和输出（AI的回答）都消耗Token。

💡 上下文窗口

每个AI模型有一个"上下文窗口"限制——就是一次对话能处理的最大Token数。GPT-4o约128K Token，Claude约200K Token。超过限制，AI就会"忘记"前面的内容。

🎒 第十七章：无Git账号的教学方案

17.1 替代方案

如果学生没有Git/GitHub账号，课堂上又不方便花时间注册，以下替代方案可以让Git部分的教学照常进行：

方案A：只讲本地Git（推荐）

操作是否需要GitHub账号课堂可做
git init（初始化仓库）不需要✅
git add .（暂存）不需要✅
git commit（提交）不需要✅
git log（查看历史）不需要✅
git checkout（回退）不需要✅
git push（推送远程）需要❌ 课后再做
✅ 核心信息

Git的核心价值——版本控制（快照 + 回退）——完全不需要GitHub账号！本地就能体验全部核心功能。远程推送是锦上添花，课后注册账号再做。

方案B：讲师演示远程操作

讲师用自己的GitHub账号演示push/pull操作，学生观看理解概念即可。把"注册GitHub + 实际push"留作课后作业。

方案C：用Gitee替代（国内）

如果需要让学生现场体验远程仓库，Gitee（码云）是国内替代方案：不需要翻墙，支持手机号注册（比GitHub更快），功能与GitHub基本一致。

17.2 概念讲解策略

Git章节的核心不是教命令，而是让学生理解为什么需要版本控制。以下策略不依赖账号：

策略1：用"撤销"类比

// 现场演示：
1. 在TRAE中用AI做一个小网页 → 效果很好 ✅
2. 告诉AI："帮我把整个页面改成蓝色主题" → 改崩了 ❌
3. 如果没用Git → 只能手动改回去（痛苦！）
4. 如果用了Git → git checkout -- . → 瞬间回到上一个好版本 ✅

一次演示胜过十页PPT！

策略2：用文件夹类比

展示"没有Git"vs"有Git"的文件管理方式（见第四章4.1节的例子），让学生感受痛点。

策略3：用TRAE的Git面板

不需要敲命令！直接在TRAE的Git面板中点按钮操作：暂存（+）→ 提交（✓）→ 查看历史。图形化界面比命令行更直观。

18.1 角色分工模型

在Vibe Coding时代，团队分工发生了变化。每个人都可以借助AI编程，但角色定位变得更加重要：

角色职责AI怎么帮人数建议
产品经理（PM）定义需求、画原型、写用户故事AI帮你把需求细化成Prompt、生成原型图1人

项目经理排期、协调、整合用AI生成项目计划、总结会议纪要1人（可兼任PM）
💡 Vibe Coding时代的关键变化

传统团队里，开发者的核心能力是"写代码"。Vibe Coding团队里，核心能力变成"描述需求"和"审查结果"。每个人都是AI的"导演"，但每个导演负责不同的"场景"。

// 推荐的团队Vibe Coding工作流：

前后端联调API
测试人员开始测试，提交Bug
  → 开发人员用AI修Bug

第四阶段：发布上线

  → 全员review最终效果

Git分支策略

main            ← 主分支，只放稳定版本
├── feature/login     ← 张三负责：登录功能
├── feature/dashboard ← 李四负责：仪表盘页面

每人在自己的分支开发，完成后merge到main

避免冲突的技巧

  • 文件级别分工：前端和后端改的是不同的文件，天然不冲突

  • 约定接口：前后端先约定好API格式（URL、参数、返回值），各自独立开发
  • 让AI解决冲突：合并时有冲突？直接让AI帮你解决

❓ 附录C：常见问题FAQ

Q：AI生成的代码跑不了怎么办？

A：按F12打开浏览器开发者工具，查看Console中的报错信息，把错误信息复制给AI，让它修复。

Q：AI写的代码和我想的不一样？

A：更具体地描述你的需求。用"我想要XXX"而不是"帮我做一个网站"。可以参考3.3节的万能模板。

Q：TRAE安装后打不开？

A：确认系统满足要求（Windows 10+/macOS 10.15+）。尝试右键以管理员身份运行。如果仍然不行，卸载后重新下载安装。

Q：Git push被拒绝了？

A：常见原因是远程有你本地没有的提交。先执行 git pull --rebase origin main，然后再push。

Q：LocalStorage数据丢了？

A：LocalStorage与浏览器和域名绑定。用不同浏览器或清除浏览数据会丢失。生产环境应该用数据库。

Q：AI可以帮我做后端吗？

A：可以！但需要安装Node.js或Python运行环境。本课程专注前端，后端可以课后自学。

Q：做完项目怎么让别人访问？

A：参考第七章的部署教程，用GitHub Pages或Vercel免费部署。

Q：我完全没有编程基础，能跟上吗？

A：Vibe Coding的核心就是用自然语言编程。你不需要会写代码，只需要会描述需求。跟着课程步骤来就行！
